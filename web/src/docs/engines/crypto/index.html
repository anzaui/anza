Cryptographic Verification

The cryptographic verification module protects Server-Templated UI (STUI) fragments from tampering, replay attacks, and unauthorized origin injection across reverse proxies, CDNs, and microservices.

Overview

When dynamic component fragments or real-time streaming updates are sent over the wire, the backend signs the payload across a canonical string:

ts:slot:html
  • ts: Unix epoch timestamp in seconds at time of generation.
  • slot: Target dock or slot identifier (e.g. feed, main).
  • html: Rendered HTML markup of the fragment.

The signature is hex-encoded in the envelope's sig field. Whoever receives the envelope (an edge worker, a proxy, another service, or your own browser code) verifies it with the matching verify helper and checks that ts is fresh. The browser library does not verify envelopes for you; see Client-Side Verification.

Asymmetric Ed25519 (Recommended)

Ed25519 uses public-key cryptography. The origin server holds the private key and signs envelopes; clients and edge proxies verify signatures using the public key without needing access to any secrets.

Backend Setup (Rust)

use anza::Setup; // Raw 32-byte private and public key files let mut setup = Setup::new("./templates"); setup.signing = Setup::ed25519("keys/origin.key", "keys/origin.pub"); let engine = setup.run()?;

Backend Setup (TypeScript)

import { Setup } from '@anzaui/engine'; import { readFileSync } from 'node:fs'; const engine = await new Setup({ root: './templates', signing: { mode: 'ed25519', privateKey: readFileSync('keys/origin_private.pem', 'utf8'), }, }).run();

Symmetric HMAC-SHA256

For single-origin deployments or internal microservices sharing a secure environment secret:

import { Setup } from '@anzaui/engine'; const engine = await new Setup({ root: './templates', signing: { mode: 'hmac', secret: process.env.STUI_SIGNING_SECRET, }, }).run();

Wire Envelope Format

All signed fragments conform to the standard wire envelope:

{ "slot": "feed", "ts": 1724771234, "html": "<ui-card class=\"stream-card\"><div slot=\"header\">Live Card</div></ui-card>", "sig": "9f83a8b2c4e1d7f005a3e4b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8", "css": null }

Client-Side Verification

The engines do not inject a key into pages. If you want browser-side checks, publish your public key in the document head yourself:

<meta name="anza-key" content="ed25519:e4d9b2c3a1f09876543210fedcba9876543210fedcba9876543210fedcba9876">

The browser library does not verify envelopes automatically: there is no built-in stream listener, and api.stream() only parses JSON. Verification is done with the engines' verify helpers (Rust crypto::ed25519, TS crypto/ed25519.ts / crypto/hmac.ts, Python anza.crypto), typically on the server or edge that relays fragments. To verify in the browser, rebuild the ts:slot:html message from the envelope, check that ts is fresh, and call crypto.subtle.verify('Ed25519', key, sig, message) with the public key from <meta name="anza-key">. verify() from @anzaui/anza/security covers HMAC and ECDSA keys only.
