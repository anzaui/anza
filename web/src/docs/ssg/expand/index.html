SSG expand: {{slug}}

This page is emitted at build time from the parametric pattern /docs/ssg/expand/:slug via ssg.expand. Unexpanded param values stay Mode B or CSR (no dist/…/index.html).

Declare expansions

page('/docs/ssg/expand/:slug', { params: [{ name: 'slug', type: String }], ssg: { expand: [{ slug: 'foo' }] }, seo: { title: 'SSG expand: {{slug}} — Anza' }, // … })

Or list values in project-level ssg.params.json keyed by the route pattern. See the HTML contract.

What actually gets emitted

Route entryResult
/docs/ssg/expand/:slugPattern remains client-matchable, but is not itself emitted as a concrete HTML file
{ slug: 'foo' }Build emits dist/docs/ssg/expand/foo/index.html and marks that concrete route as SSG-backed
Unlisted slugNo Mode A HTML file; serve with Mode B templates or leave CSR-only

This keeps one parametric route definition in source while letting the build output only the concrete public URLs you explicitly declare.

Module-level vs project-level expansion

Use the page module when the expansion list belongs to that route:

page('/docs/ssg/expand/:slug', { params: [{ name: 'slug', type: String }], ssg: { expand: [ { slug: 'foo' }, { slug: 'bar' } ] }, seo: { title: 'SSG expand: {{slug}} — Anza', description: 'Build-time parametric expansion example for {{slug}}.' } }, import.meta.url);

Use ssg.params.json when content inventory is better maintained outside the page module:

{ "/docs/ssg/expand/:slug": [ { "slug": "foo" }, { "slug": "bar" } ] }

Rules to remember

  • Expand only public values you can know at build time.
  • Do not guess authenticated or personalized params just to force SSG.
  • {{slug}} placeholders in SEO fields interpolate per concrete expansion.
  • Soft-nav still fetches the page fragment, not the full SSG document.

Verify

npm run build test -f dist/docs/ssg/expand/foo/index.html node tasks/ssg-contract-check.js

For a local smoke test, serve dist/ as the site root and open /docs/ssg/expand/foo.

Build pipeline

Route extraction (tools/src/extract) reads page({ ssg: { expand } }) from each module and merges project-level ssg.params.json. For every expand entry whose params fully substitute the pattern, the build emits a concrete RouteInfo path — parametric patterns with remaining : segments are client-matchable only.

SourcePrecedence
page({ ssg: { expand: [...] } })Co-located with the route module
ssg.params.jsonKeyed by route pattern string; merged at extract time
page({ seo: { … } }){{param}} placeholders interpolate per concrete expansion in emitted HTML head

Warnings log when an expand entry does not match the pattern or omits a required param name — the build continues but skips invalid entries.
