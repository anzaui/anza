Storage

The Anza storage layer provides a unified, tiered storage surface. It integrates LRU memory caching, IndexedDB, Origin Private File System (OPFS), and the Cache API under a single facade with automatic tier fallback, TTL support, and transparent gzip compression.

vs state.storage: use @adukiorg/anza/storage for general key/value, files, and HTTP cache tiers. Use state.storage (PlatformStorage) for reactive-store snapshots keyed by object-store name — including filter-function query. If you use both, give them different IndexedDB database names (both default to platform-db — see Troubleshooting).

What You Get

  • Unified API — storage.get, storage.set, storage.delete with tier selection
  • Multiple tiers — memory (LRU), idb (IndexedDB), opfs (file system), cache (Cache API)
  • TTL — per-key expiry honored across all tiers
  • Compression — automatic gzip for values over 64KB in IndexedDB (when Compression Streams exist)
  • Write journaling — localStorage-backed journal for crash recovery on IDB writes
  • Quota management — proactive checks, eviction, and warning callbacks
  • List / clear / estimate — storage.list, storage.clear, storage.estimate / persist

import { storage } from '@adukiorg/anza/storage';

One-File Example

import { storage } from '@adukiorg/anza/storage'; storage.configure({ idb: { name: 'app-kv' } }); // Basic IDB read/write await storage.set('user', { name: 'Alice' }); const user = await storage.get('user'); // Memory tier for hot data await storage.set('session', { token: 'abc' }, 'memory'); // TTL — expires in 5 minutes await storage.set('temp', data, { tier: 'idb', ttl: 300000 }); // OPFS for large files await storage.set('blob', fileBuffer, 'opfs'); // Cache tier await storage.set('config', settings, 'cache'); const keys = await storage.list();
